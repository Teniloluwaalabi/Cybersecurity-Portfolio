# Compliance & Framework Mapping

## Overview

This section maps selected security recommendations from the FinTrust risk assessment to relevant cybersecurity framework areas.

The purpose of the mapping is to demonstrate how security risks can be addressed through structured governance and control practices.

> Note: This is a portfolio exercise based on publicly recognized framework concepts. It is not a formal compliance audit or certification assessment.

---

## NIST Cybersecurity Framework Mapping

| Security Area | Recommended Control | NIST CSF Function |
|---------------|---------------------|--------------------|
| Asset Management | Maintain an inventory of critical systems and data | Identify |
| Risk Assessment | Regularly identify and assess cybersecurity risks | Identify |
| Access Control | Implement MFA and least privilege | Protect |
| Security Awareness | Conduct employee cybersecurity training | Protect |
| Patch Management | Identify and remediate system vulnerabilities | Protect |
| Security Monitoring | Monitor systems and security events | Detect |
| Incident Response | Establish and test an incident response process | Respond |
| Backup & Recovery | Maintain and test backups | Recover |

---

# NIST CSF Functions

The recommendations align with the five core NIST Cybersecurity Framework functions:

### Identify

FinTrust should understand its assets, business environment, cybersecurity risks, and vulnerabilities.

Examples:

- Asset inventory
- Risk assessments
- Vulnerability assessments

### Protect

FinTrust should implement safeguards to reduce cybersecurity risk.

Examples:

- MFA
- Access controls
- Security awareness
- Data protection
- Patch management

### Detect

FinTrust should identify potential cybersecurity incidents in a timely manner.

Examples:

- Security monitoring
- Logging
- Endpoint detection
- Alerting

### Respond

FinTrust should have processes for responding to detected cybersecurity incidents.

Examples:

- Incident response procedures
- Containment
- Communication
- Investigation

### Recover

FinTrust should restore affected systems and improve resilience following an incident.

Examples:

- Backups
- Recovery procedures
- Restoration testing
- Lessons learned

# Governance Considerations

A mature information security program should not rely solely on technical controls.

FinTrust should establish:

- Clearly defined security responsibilities
- Documented policies and procedures
- Regular risk assessments
- Management oversight
- Security awareness programs
- Control reviews
- Incident reporting processes
- Third-party risk management
- Continuous improvement

---

# Compliance Monitoring

FinTrust should periodically review its security controls to determine whether they remain effective.

Recommended activities include:

1. Review security policies.
2. Reassess cybersecurity risks.
3. Review user access.
4. Evaluate security incidents.
5. Review third-party risks.
6. Test backup and recovery procedures.
7. Assess security control effectiveness.
8. Document findings and remediation activities.

---

# Conclusion

Frameworks such as the NIST Cybersecurity Framework and ISO/IEC 27001 provide structured approaches for managing information security risks.

FinTrust should use these frameworks as references for developing and improving its security governance program while considering applicable legal, regulatory, contractual, and business requirements.
