# Incident Response Plan – FinTrust Financial Services Ltd.

## Project Overview

This project demonstrates the development of a structured **incident response plan** for a fictional fintech organization, FinTrust Financial Services Ltd.

The scenario involves a suspected **phishing attack that results in the compromise of an employee account and suspicious access to internal systems**.

The project follows the incident lifecycle from initial detection and analysis through containment, eradication, recovery, communication, and lessons learned.

> **Disclaimer:** FinTrust Financial Services Ltd. is a fictional organization created for educational and portfolio purposes. This project does not represent a real security incident or professional incident-response engagement.

---

## Incident Scenario

A security alert is triggered after unusual login activity is detected on an employee account.

The investigation indicates that the employee may have entered their credentials into a fraudulent phishing page. Shortly afterward, the compromised account is used to access internal systems from an unusual location.

The security team must determine:

* Whether the account has been compromised
* What systems may have been accessed
* Whether sensitive information was exposed
* How to contain the incident
* How to remove the attacker's access
* How to safely restore normal operations
* What improvements should be implemented afterward

---

## Project Objectives

The objectives of this incident response exercise are to:

* Establish a structured incident response process
* Classify and prioritize the security incident
* Document detection and investigation activities
* Define containment procedures
* Develop eradication and recovery actions
* Establish an incident communication process
* Document the incident timeline
* Identify lessons learned and corrective actions
* Produce a final incident report

---

## Incident Response Lifecycle

The response process is organized into the following stages:

**1. Preparation**
Establish policies, roles, tools, communication channels, and response procedures.

**2. Detection & Analysis**
Identify suspicious activity, validate the incident, collect relevant information, and determine its severity.

**3. Containment**
Limit the incident's impact and prevent further unauthorized activity.

**4. Eradication**
Remove the underlying cause of the incident and eliminate unauthorized access.

**5. Recovery**
Restore affected systems and services while monitoring for signs of recurring activity.

**6. Lessons Learned**
Review the incident, identify weaknesses, and implement improvements.
