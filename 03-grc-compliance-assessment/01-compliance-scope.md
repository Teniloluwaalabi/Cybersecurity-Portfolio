# Compliance Scope – FinTrust Financial Services Ltd.

## 1. Purpose

This document defines the scope, objectives, assumptions, and assessment boundaries for the GRC and compliance assessment of FinTrust Financial Services Ltd.

The purpose is to establish a clear basis for evaluating the organization's information-security controls and identifying areas requiring improvement.

> **Disclaimer:** This is a fictional cybersecurity portfolio exercise. It is not a formal regulatory audit, certification assessment, or legal/compliance opinion.

---

## 2. Organization Profile

**Organization:** FinTrust Financial Services Ltd.
**Industry:** Financial Technology (FinTech)

FinTrust provides:

* Online banking services
* Mobile payment services
* Digital wallets
* International money transfers
* Merchant payment solutions

The organization processes sensitive customer, financial, and business information.

---

## 3. Assessment Objectives

The assessment aims to:

1. Evaluate selected information-security controls.
2. Identify governance and compliance gaps.
3. Map controls to recognized cybersecurity frameworks.
4. Identify risks associated with control weaknesses.
5. Prioritize remediation activities.
6. Provide practical recommendations for improving security governance.
7. Demonstrate a structured GRC assessment methodology.

---

## 4. Assessment Scope

The assessment covers the following security and governance areas:

| Area                     | Assessment Focus                                    |
| ------------------------ | --------------------------------------------------- |
| Asset Management         | Identification and management of information assets |
| Access Control           | User access, privileges, and authentication         |
| Security Awareness       | Employee security training and awareness            |
| Vulnerability Management | Identification and remediation of vulnerabilities   |
| Incident Response        | Incident detection, response, and documentation     |
| Data Protection          | Protection of sensitive information                 |
| Third-Party Risk         | Security assessment of external providers           |
| Business Continuity      | Recovery and resilience capabilities                |
| Security Monitoring      | Logging, monitoring, and detection                  |
| Governance               | Security policies, responsibilities, and oversight  |

---

## 5. Frameworks Used

### NIST Cybersecurity Framework

The assessment references the five NIST CSF functions:

* **Identify**
* **Protect**
* **Detect**
* **Respond**
* **Recover**

These functions provide a structure for evaluating cybersecurity activities across the organization.

### ISO/IEC 27001

The assessment also considers relevant information-security management practices associated with ISO/IEC 27001, including:

* Information security policies
* Asset management
* Access control
* Human resource security
* Operations security
* Supplier relationships
* Incident management
* Business continuity

---

## 6. Assessment Boundaries

### Included

The assessment includes:

* Information-security governance
* Selected security controls
* Security policies and procedures
* Risk-management practices
* Access management
* Employee security awareness
* Incident-response capabilities
* Third-party security considerations
* Business continuity controls

### Excluded

The assessment does not include:

* Penetration testing
* Vulnerability scanning
* Source-code review
* Digital forensics
* Technical configuration testing
* Financial auditing
* Legal advice
* Formal regulatory certification

---

## 7. Assessment Assumptions

For this portfolio exercise, the following assumptions apply:

* FinTrust operates cloud-based applications and infrastructure.
* Employees access corporate systems remotely.
* The organization processes sensitive customer and financial information.
* Security policies and controls exist but may not be consistently implemented.
* Control effectiveness is assessed based on the fictional scenario and available documentation.
* Identified gaps represent hypothetical findings for educational purposes.

---

## 8. Assessment Rating

Controls will be assessed using the following maturity ratings:

| Rating                  | Description                                                 |
| ----------------------- | ----------------------------------------------------------- |
| **Effective**           | Control is implemented and operating as expected            |
| **Partially Effective** | Control exists but has implementation or effectiveness gaps |
| **Needs Improvement**   | Control exists but significant weaknesses are present       |
| **Not Implemented**     | Required control or process has not been established        |

---

The assessment will follow this process:

**1. Define Scope**
↓

↓
**3. Assess Control Effectiveness**
↓
**4. Map Controls to Frameworks**
↓
**5. Identify Gaps**
↓
**6. Assess Associated Risks**
↓
**7. Develop Remediation Actions**
↓
**8. Produce Final GRC Report**
